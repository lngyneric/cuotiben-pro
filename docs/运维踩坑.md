# 运维踩坑记录

2026-10-15 cuotiben-pro 上线实录。可由约定预防的，记下来避免重犯。

## 1. better-auth 密码最短 8 位

- 现象：6 位密码登录报含糊的 `http error`，查了很久。
- 根因：`PASSWORD_TOO_SHORT`——better-auth 要求密码 ≥ 8 位。
- 约定：初始密码一律 ≥ 8 位；手动插库绕不过 better-auth 的哈希验证，别走这条路，直接走 `/sign-up` 注册（注册即自动登录）。

## 2. 换域名 / 改 Worker 名后，auth 的 origin 配置必须同步

- 现象：旧地址 `shipany-tanstack.lng-yn.workers.dev` 上注册报 `Invalid origin`。
- 根因：better-auth 只认配置里的 origin（`VITE_APP_URL` / trustedOrigins），跟线上域名对不上就拒绝。
- 约定：改名或换域后，第一时间检查 `deploy.yml` 里的 `VITE_APP_URL` 与 auth 配置是否指向新域名；修好后引导用户去新地址重新注册。

## 3. D1 migration 需要 token 带 D1 权限，否则静默跳过

- 现象：`wrangler d1 migrations apply` 没报错也没建表（`|| echo "…skipped"` 把失败吞了）。
- 根因：Cloudflare API token 没有 D1 权限。
- 约定：建 token 时勾选 D1 权限；apply 之后用 `SELECT name FROM sqlite_master WHERE type='table'` 查表验证，别信 echo。

## 4. 影响线上部署的改动，当天就 PR 进 main

- 现象：2026-10-15 当天 4 个运维提交（D1 SQL workflow、AUTH_SECRET、password fix、Worker 改名）全部滞留本地分支，而 `deploy.yml` 只在 push main 时自动部署——下次任何人 push main 都会把线上配置回滚到模板默认值。
- 约定：worker 名、secret、D1、URL 这类部署配置改动，当天就走 PR 进 main，不在本地过夜。
